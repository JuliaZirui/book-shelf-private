# 内容要点图执行规范

仅适用于内容要点图。制作前阅读[字体规范](字体规范.md)、[排版规范](排版规范.md)和[品牌色板](品牌色板.md)。本图选用通用字体角色表、标准标题和标准正文组件；信息结构、模块布局与验收只在本文件维护。

## 输入与确认内容

提炼主题、一句有判断的核心主张及2–4个章节。确认每章的问题、关系类型及依据、主／辅角色、视觉模型，并附整页区域草图与预计高度；合并进SKILL.md规定的一次确认。内容不足时回看用户笔记，不以想象补齐。

## 1. 风格目标与优先级

目标是有清晰编辑层级的书籍知识海报：主题可辨、章节可扫读、概念与解释可区分，图标帮助识别，模型表达关系。参考图共有的是信息组织，不是共同字体、比例或装饰特效。

无底部总结；最多两层容器。轻量细线、实色编号徽章、浅色图标底座可用于建立秩序，不要求全用。

失败修正顺序：内容与关系 → 可读性 → 主次及空间 → 对齐 → 图标和装饰。不得牺牲事实来获得视觉多样性。已经确认的文案，不因排版自行改变含义。

## 2. 整页结构与容量

每页先选一种主导结构，辅助模块最多再用两种组件家族。不是每章必须换一种图。

- **机制突出型**：一个重要机制/分类映射区，其他为紧凑补充。主区可先占正文区约35–45%，再按实测调整；适合安全边际、生命周期等有清晰关系的内容。
- **导航清单型**：导航占有效宽度约24–32%，其余给有共享字段的行列表；适合为什么/如何/行动等层级。左右各行对应，不把章节序列画成时间线。
- **章节组合型**：通栏主章节 + 紧凑列表或底部两栏；适合习惯、工具与行动体系。不同章节可用相同组件，无需为了变化硬造关系。

模块间距20px；模块内边距从24px起步，可按图标调整至32px。列宽由所选公共组件的可用宽、列数和间距计算，再扣除内边距及图标占位。浅底概念格并非必备，能用对齐/细线分组时不用逐格套框。

先按公共规则排标题组，再分配正文区。不能沿用旧小标题的固定坐标。

每个模块记录：问题、主张、主/辅角色、关系类型、节点/条目、解释、来源、组件、区域框。模块高度 = 上下内边距 + 章节头实际高度 + 头部间距 + 内容测量高度；再按主次分配余量。不得用固定142px节点适配所有字数。

诊断空白时看实际内容包围盒到容器边缘的距离。若一侧空白超过内边距两倍且没有连线路径、分组或视觉中心用途，检查是否应收紧/重排；这不是自动扣分阈值。留白不能通过添加空话填满。

## 3. 调用统一文字规则

必读[字体规范](字体规范.md)的角色表和字体资源，再读[排版规范](排版规范.md)的主副标题适配和正文排版。这里不复制参数表，避免三处字号再次分叉。

要点图的文字依次映射为页面主标题、页面副标题、一级章节标题、要点标题、正文、解释或次级标注。核心主张属于副标题，章节名不属于副标题。主要观点作为正文，补充例子/原因/条件作为解释；同义重复不能充当解释。不要求每条都填满所有层级。

例如“降低启动阻力”为要点标题，“提前备好所需物品”为正文，“例如把书放在随手可拿的位置”为解释。例句仅用于说明角色，不直接作为书籍事实。关键条件须贴近对应观点呈现。

## 4. 色彩与图形语言

背景主色按品牌六色原值。正文放白色/同主题浅色面板，深色正文可用#102B42；青色主题可用#173C46。主色用于章节与语义图标，辅助底色可由主色与白色混合8–12%得到，保持整页一致。黄/浅青/灰主题的正文、细线和小图标使用足够深的同色系或深中性色，不能把浅背景色直接当小字色。

外面板圆角20–24px，内层12–16px。分隔线1.5–2px，颜色轻于文字；一章选择横向行分隔或纵向分栏，不再同时加满边框、底座、虚线、徽章。圆角本身不产生层级，一级章节需要独立标识。

章节标识推荐：48–56px实色圆形编号 + 通用一级章节标题 + 必要的浅色分隔线。不要同时堆“编号、章节图标、大徽章”三套标识。

语义图标默认44–56px、描边约3px；必要时用60–72px浅色底座。主概念图可72–96px。按光学重量对齐，图标占位固定、文字统一起点。缩至360px后细节仍须可辨；简化细节优先于不断加粗。允许同一套规范内的实心/线性层级区分，但同组同风格。

按概念选图标：价格=报价标签/走势图，估值=计算或放大镜，契约=签字文档，记录=日志，监督=双人检查等。相同概念复用，不同概念不得无理由共用眼睛/文档。库不支持的名称明确报缺失，不静默回退。图标配文字，不用emoji，不从截图裁图标。

参考图主要使用语义符号和小型概念插图，没有统一要求大型场景插画。只有独立插图能帮助解释时才制作；不能以增加插画补救松散的信息结构。

## 5. 组件验收合同

| 组件 | 应表达什么 | 必须检查 |
|---|---|---|
| 开放分栏 | 并列概念 | 字段顺序一致；共享对齐；不用箭头暗示先后 |
| 行式解释 | 对象/行动与解释对应 | 可用“关注对象/阅读提醒”等表头；跨行不串读；长解释有宽度预算 |
| 对照 | 同维度对象的区别 | 两边同字段；若只说明概念不同，可用“不等于”，不暗示永不相等 |
| 过程 | 明确顺序 | 箭头端点附着对应节点，方向有依据，节点与箭头之间留安全间隔 |
| 循环 | 返回先前节点 | 存储from/to与边含义，视觉可沿路线回到起点；文字遮挡线时使用标签背景或规范间断，仍可判断是一条边 |
| 定性距离/区间 | 两端概念及方向 | 标“示意”；若表达较低价格与估计价值，明确方向/条件，而非只画无方向长线 |
| 分类矩阵 | 同字段比较多个类型 | 每类字段一致，缺项明示；不能为凑齐6格杜撰类型 |

例：习惯叠加优先画“已有习惯完成后 → 执行新行为”，把“之后”作为关系标签；若内容还讲两分钟启动，将它列为新行为的执行提示，不把时间连接词当作与行为并列的第三实体。

## 6. 多阶段生成与检查

A 内容阶段：整理有来源的短标签和增量解释（条件、区别、动作或依据），不扩写同义句；生成关系定义，记录节点及边的含义。区分作者表述与编辑归纳；无关系依据时用清单，不为多样性编造流程、比例、曲线或排名。例“关注报价 → 留意市场如何运行”增加的信息很少，应回查笔记获得真实区别，而非扩写同义句。

B 灰度阶段：使用真实文字，确定主次、区域和文本行数。保存灰度试排；只检查形状和标题能否识别章节、重点与阅读顺序。若不成立，改布局后再上色。

C 成图阶段：应用色板、字体、统一图标。中文与关系图使用可编辑文字或可重建的确定性布局；如需生成插图，仅生成独立无字资产后组合。先检查渲染器支持的组件，未支持时实现或明确采用语义等价替代。按公共画布尺寸导出原图及360px宽预览，保留可编辑文本或重建脚本。

D 验收阶段：

1. 内容/语义：已确认文字与渲染文字核对；每条边有类型与依据；模型未增加虚假的数字/因果/排名。
2. 自动几何：按字体规范和公共排版规范验证文字角色、实际字体、字重、字号、边距、标题适配和间距；文字真实包围盒与所属容器内边距、字形裁切、标题适配、图标/文字/箭头碰撞；容器自身登记父子关系；连接线计算描边宽度与箭头头部范围。不能只用“位于任意一个白面板内”代替所属模块检查。
3. 人工视觉：每张原图检查标点、断行和笔画；360px图检查五秒内能否辨认主题、章节和主要关系，若清单型则看层级和行对应。记录哪个区域偏空、哪个标题抢眼、哪个图标不清楚，并写出修正。不能仅写“美观、通过”。
4. 配置复现：文案/节点从配置读取，布局参数显式化；未知组件停止或明确说明等价替代。专用脚本单独标注，不能把旁写的JSON说明当作渲染数据源。

一次完整审查后修正，复查受影响项；重大结构仍未解决时再迭代。迭代次数不等于合格标准。交付时分开列自动通过、人工已查看和未验证；不宣称此规范已经实现通用渲染器。

## 实现参考

项目当前未保留可直接复用的历史试排渲染器；制作时需按本文件第1–6节的结构选择、文字规则、色彩与图形语言及组件验收合同从头实现或改造现有渲染流程，不依赖已不存在的外部历史文件，也不能省略第6节D阶段的验收步骤。
