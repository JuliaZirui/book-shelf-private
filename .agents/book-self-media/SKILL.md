# 图书自媒体 Skill

## 目标

把“一本书”稳定加工成三组可直接用于自媒体生产的素材：

1. **图书资料卡 + 打分图**：联网核验基础信息，补全特色标签，并把用户的五维评分做成雷达图。
2. **关联书籍表 + citation 图**：寻找 4–6 本真正有逻辑关联的书，解释关系并绘制阅读路径树。
3. **结构图海报**：根据用户提供的内容/笔记与可靠资料，提炼成一张层级清晰、适合传播的竖版知识结构图；支持输入 HEX 色号改变整体色系。

默认使用中文输出。除非用户明确要求，只做与图书自媒体有关的信息，不扩展成冗长书评。

为本次涉及的产物创建对应书籍文件夹，并把生成内容写入其中：

| --- | --- | --- |

执行时遵守：

- 完整流程开始时创建上述三个书籍文件夹；用户只要求某一步时，只创建对应目录。
- 同一本书再次处理时复用已有文件夹，不另建重复目录。
- 修改已有产物时优先更新原文件；需要保留旧版时使用 `-v2`、`-v3` 后缀。
- 不把生成文件散落在素材库根目录，也不放进其他书籍的文件夹。
- Markdown 文件末尾保留本次使用的来源链接与查询日期。
- 回复用户前确认文件实际存在，并提供可点击的绝对路径。

# 二、联网与事实核验规则

处理一本真实出版图书时，先联网搜索必要资料，再输出结论。

## 必查信息

- 中文书名 / 原书名（如适用）
- 作者
- 原版首次出版时间
- 用户指定或当前常见中文版本的出版社
- 豆瓣评分（若可查）
- 图书主题、核心概念、目录/官方简介等用于辅助分类的信息

## 来源优先级

优先使用：

1. 出版社官网、作者官网、图书官方页、ISBN/国家图书馆等权威书目信息
2. 豆瓣图书页（评分）
3. Goodreads、Google Books、Internet Archive、出版社目录页等可靠书目信息
4. 大型书店/电商的出版社信息，仅作为交叉核验
5. 媒体书评、学术资料，用于理解关联关系，不用于替代基本书目信息

## 核验要求

- **豆瓣评分是动态数据**：写成 `7.7（截至 2026-08-30）` 这类形式。若无法可靠获取，则写 `暂未可靠获取`，绝不猜测。
- **出版社必须绑定版本**：如果一本书有多个中文版本，不要把不同版本的出版社和年份混在一起。必要时写 `中信出版社（所查中文版本）`。
- **出版时间区分原版与中文版**：关联书籍表默认使用“原版首次出版年份”。基本信息如果用户关注中文版，可补充中文版本年份。
- 遇到书名重名、译名不一致、作者不确定时，先通过搜索消歧；若仍无法确定，明确标注不确定项。
- 不把营销文案、二手摘要当成事实来源。

# 三、步骤 1：图书资料卡

## 输出格式

固定先输出：

# 基本信息

| 项目 | 内容 |
| --- | --- |
| 书名 | 《目标书名》 |
| 作者 | 作者姓名 |
| 出版社 | 出版社（所查版本） |
| 豆瓣评分 | X.X（截至 YYYY-MM-DD） |

## 特色信息

| 项目 | 内容 |
| --- | --- |
| 个人打分 | 用户已提供则照录；未提供写“待填写” |
| 道（世界观）/法（方法论）/术（技巧）/器（工具） | 选最主要的 1 项，必要时写“道为主，兼具法”；不要四项全选 |
| 分类 | 1–3 个高度概括的主题，如“风险管理、认知、投资” |
| 适合人群 | 在 `入门 / 初级 / 进阶 / 高阶` 中将最合适的层级**加粗**；可多选但最多 2 个连续层级 |
| Keywords | 3–6 个可用于自媒体标签、标题或海报的关键词，使用中文短语，逗号分隔 |

## “道法术器”判断标准

- **道（世界观）**：改变“怎么看世界/人/社会/商业/风险”的底层框架。
- **法（方法论）**：给出一套可迁移的问题解决方式、思考流程、原则体系。
- **术（技巧）**：偏具体操作、话术、执行技巧、局部策略。
- **器（工具）**：偏模板、清单、软件、指标、模型、量表、工具箱。

判断时回答“这本书最主要改变读者什么？”而不是“书里出现过什么”。

## 分类与 Keywords 规则

- 分类要稳定、可复用，适合未来系列化管理。
- Keywords 要有传播性，但不能变成空泛词，如“成长”“人生”单独使用时信息量太低。
- 优先选书中真正有辨识度的概念，如“极端斯坦、叙事谬误、冗余、不可预测性”。

## 资料卡后的简短说明

表格后可用 1–2 句话说明：
- 为什么判为“道/法/术/器”中的这一类；
- 为什么推荐该阅读层级。

不要写成长篇书评。

# 四、步骤 2：关联书籍表

## 数量

默认 **5 本相关书 + 目标书本身 = 6 行**。

若确实没有足够高质量关联，可少于 5 本，宁缺毋滥。

## 选择逻辑

不要只做“同类畅销书推荐”。关联书籍优先覆盖这些关系：

1. **理论前置**：目标书的重要思想来源、哲学或学术基础。
2. **同主题互补**：从另一学科或另一角度解释相同问题。
3. **作者体系延伸**：同作者更早/更晚的关键作品。
4. **行动层延伸**：目标书提出问题，另一本书给出方法。
5. **对照/反面视角**：概念相近但边界不同，能帮助读者区分。

尽量让 4–6 本书形成一条“阅读路径”，而不是随机列表。

## 排序规则

默认按“思想路径 + 出版时间”综合排序：

**理论前置 → 早期相关经典 → 目标书 → 后续延伸 → 对照观点**

如果目标书本身很早，也可以按年代自然排序。

## 输出格式

| 书名 | 作者 | 出版时间 | 与《目标书名》的相似点 |
| --- | --- | ---: | --- |
| 《相关书 A》 | 作者 | 19XX | 80–140 字，解释具体概念上的连接，不写空泛的“主题相似”。 |
| 《相关书 B》 | 作者 | 19XX | …… |
| 《目标书名》 | 作者 | 20XX | 用 80–140 字概括本书在这条阅读路径中的核心位置。 |
| 《相关书 C》 | 作者 | 20XX | …… |

## 相似点写作公式

每一格尽量包含：

**这本书讲什么关键概念 + 它与目标书在哪里相接 + 两者差异/阅读价值（如有）**。

示例风格：

> 奈特区分了“可计算的风险”和“不可计算的不确定性”；这几乎是理解《黑天鹅》的理论前置：真正改变世界的，往往不是已知风险，而是未知的不确定性。

避免：

> 两本书都讲风险，很值得一起读。

## 事实要求

- 出版时间默认写**原版首次出版年份**。
- 作者名、年份必须核验。
- 若译名存在多个版本，优先使用中文读者最熟悉的译名；必要时括注原名。

## 2.1 Citation 树状图

完成关联书籍表后，直接按本节定版模板生成 `1_citation树状图/<书名>/citation树状图.png`。不再从其他 V1/V2 示例重新提取或改造版式。

### 定版模板与输入

Citation 图已定版。固定视觉参考为 `assets/citation-template-reference.png`，固定渲染器为 `scripts/render_citation.py`。以后生成时不得重新设计版式；用户只需提供：

1. **标题/书名**：默认图标题为 `《书名》阅读路径`。
2. **背景配色**：接受 HEX 或明确颜色描述；该颜色作为纯色背景，自动选择高对比文字和强调色。

用户无需再提供作者、出版年份、关联书、封面或关系文字。应自动联网核验目标书，选择 4 本最有逻辑关系的书，查找正面平视封面，撰写关系短语并填充 `citation配置.json`。除非用户明确要求改版，任何新书都复用定版模板，只替换书目内容、封面和背景配色。

默认使用 **目标书 + 4 本高质量关联书 = 5 个节点**。图像尺寸固定为 1086×1448（约 3:4）。

### 不可变版式

- 顶部居中显示 `《书名》阅读路径`。
- 五个节点按原版首次出版年份从上到下排列，右侧使用同序纵向时间轴。
- 定版尺寸参数固定为：关联书封按基准尺寸放大 1.1 倍，目标书封按基准尺寸放大 1.35 倍；全局文字在基准字号上增加 2px，所有封面下方的书名与作者再额外增加 2px，主标题保持当前 58px。
- 防遮挡排版：按目标书所在年份位置使用渲染器的最新锚点预设；标题与主角封面至少留 24px，作者与相邻关系说明至少留 20px，最后作者底部至少留 20px。关系文字按主干与封面之间的实际可用宽度自动换行，文字距离书封至少 18px；保留全部原文与现有字号，仅调整换行和间距。
- 关系文字必须根据实际字高定位在对应分支线上方，并与连线至少保留 14px 空隙；不得出现文字压线或穿线。
- 时间轴默认位于 `x=1040` 的右侧安全区；年份标签完整显示，并与右侧封面保持可见间距，不得被封面遮挡。
- 目标书位于自己的真实年份位置，以 1.35 倍目标书基准封面形成第一视觉层级，年份使用强调色。
- 目标书封面下方只显示《书名》和作者两行，不显示 Keywords、标签胶囊、定位语或其他附加文字。
- 关联书节点在主干左右交错；书封下方固定两行：第一行《书名》，第二行作者。
- 关系文字放在书封与主干之间，通常两行，沿用简短、具体的原文风格。
- 分支采用“长水平线 + 主干附近紧凑四分之一圆角”。早于目标书的节点向下弯接向目标书；晚于目标书的节点向上弯汇入主干。
- 不添加书封外框、卡片底板、圆角容器、阴影、装饰图标或额外说明区。
- 纵向排布应充分利用画布：首个节点靠近标题下方，最后节点接近底部安全区，避免底部大面积空白。

其余规则如下：

- 默认 1086×1448 竖版、纯色背景、极简编辑设计。
- **默认必须联网寻找真实书封**：目标书及每本关联书都优先使用可核验的实际出版封面，不用纯文字代替已有封面。
- 封面来源依次优先：出版社/作者/官方图书页、ISBN 或图书馆页面、Google Books/Open Library、大型书店或可靠媒体的图书页面。优先选择用户指定版本；未指定时选择清晰、常见且书名作者可辨认的中文版本。
- 封面必须优先选择**正面、平视、矩形完整**的图片：不使用倾斜透视图、手持实拍、书脊外露、封底连拍、书堆照片、3D 样机或带大面积宣传背景的合成图。下载后先目视检查；不合格就继续检索，不因清晰度高而放宽角度要求。
- 把下载的封面统一保存到 `1_citation树状图/<书名>/covers/`；同时生成 `封面来源.md`，逐本记录书名、作者、本地文件名、版本说明、来源页面、原图链接和查询日期。
- 书封属于**不可重绘的原始素材**：不得用图像生成模型重新画封面，不得改动封面内的书名、作者、出版社、图案和颜色。允许等比缩放和轻微裁掉网页留白；圆角、阴影或描边只有原模板本来就有时才保留，不额外添加。
- 为保证封面与中文文字准确，优先用脚本、HTML/SVG、Canvas 等确定性排版方式合成 citation 图；不要让图像生成模型在一张图里重绘多本真实封面。
- 必须复用本 Skill 的 `scripts/render_citation.py`：在书籍目录保存 `citation配置.json`，填入封面相对路径、书名、作者、年份和关系短语，再渲染为 `citation树状图.png`。
- Citation 图的纵向节点严格按原版首次出版年份从上到下排列；目标书不因“主角”身份强行置顶，而是在自己的年份位置用 1.35 倍目标书基准封面和强调色突出。五节点布局应按目标书所在年份位置自动选择纵向锚点，确保放大后的封面、书名和作者完整落在画布安全区；默认不为封面增加卡片底板、外框或容器。
- 连线弧向应表达时间关系：早于目标书的前置节点在水平线末端**向下弯**并接向目标书；晚于目标书的延伸节点**向上弯**汇入主干。不能把所有分支机械地画成同一弧向。
- 修改已有 citation 图时遵循“最小改动”：用户只要求替换封面，就必须保持原图的背景、布局、留白、连线、时间轴、颜色和关系文字不变；不得顺手改版或重新压缩文案。
- 用白色主干和圆滑分支连接相关书；沿用示例的“长水平线 + 主干附近紧凑四分之一圆角”结构：大部分分支保持水平，只在接近竖向主干时平滑弯入，不把整条分支拉成大弧线，也不使用尖锐折角或斜切直线。每条分支写 8–24 字的具体关系短语，不使用“主题相似”一类空话。
- 已有图或已获用户确认的关系文字应逐字沿用；只有用户明确要求重写时才更新。
- 相关书节点分布在主干两侧，显示真实书封。每个封面下方固定使用两行独立文字：第一行写《书名》，第二行写作者；不得把“作者｜书名”挤在同一行，也不得用图内封面文字代替外部标签。
- 右侧设置纵向时间轴，按原版首次出版年份从早到晚排列，使用上/下箭头收束。
- 目标书应在时间轴和树状关系中被清晰突出；若按思想路径排序比纯年代更重要，可让连线表达思想路径，但年份仍必须准确。
- 只有在按上述来源顺序检索后仍无法可靠取得封面时，才使用清晰、统一的纯色书名占位卡；必须在 `封面来源.md` 标为“未找到可靠封面”，不得伪造真实版次或出版社视觉。
- 背景色优先取目标书封主色或用户指定 HEX；文字与连线必须高对比。
- 控制文字密度，手机端可读；生成后逐字核对封面是否对应正确图书，并核对外部书名、作者、年份和关系短语，错字只做单点编辑。

# 五、步骤 3：结构图海报

第三步不是简单把目录搬到图片里，而是把内容变成**“一眼能看懂这本书在讲什么”的知识结构图**。

## 3.1 先生成“制图提纲”

在调用图像生成前，先把结构压缩为：

- 1 个总标题
- 3–6 个一级模块（最佳 4–5 个）
- 每个一级模块 2–4 个二级点
- 只有在必要时保留三级点，每个二级点最多 1–2 个

总文字量默认控制在 **180–320 个汉字**。若用户明确要求“只保留主干、二级、三级”，优先压缩而不是塞满。

## 3.2 内容组织原则

优先按“思想逻辑”重组，而不是照抄目录。常见结构包括：

- **问题 → 原因 → 核心机制 → 应对方法 → 启示**
- **世界观 → 方法论 → 实践 → 风险/边界**
- **概念 A / B / C → 相互关系 → 最终结论**
- **过去 → 现在 → 未来**

用户提供自己的大纲时：

- 保留用户的核心判断和命名；
- 合并重复项；
- 删除例子堆砌；
- 优先保留能体现本书独特性的概念；
- 不把用户的个人思考误写成“作者原话”。

## 3.3 海报视觉规格

默认：

- 竖版 `3:4`
- 纯色背景
- 主色由用户输入 HEX 控制；未指定时，从书封/主题选择一个沉稳、阅读友好的主色
- 整体使用**同色系深浅变化 + 高对比文字**
- 风格：简洁、理性、知识卡片、编辑设计感，不做花哨插画
- 顶部：书名/知识结构标题
- 中部：清晰的树状、分区式或纵向流程结构
- 底部：可留少量视觉收束，不塞来源、二维码或无关装饰

## 3.4 HEX 配色规则

当用户输入如 `#74bfcc`：

- 该颜色作为主背景或主视觉基色；
- 自动生成同色系的深色标题/浅色卡片层级；
- 确保文字与背景对比充分；
- 不擅自换成完全不同的色相；
- 若色号太亮导致白字不可读，允许将正文改为深色字，而不是改变用户指定主色。

## 3.5 文字排版要求

- 一级标题：短，最好 4–10 字。
- 二级点：最好 6–16 字。
- 避免完整长句堆叠。
- 中文标点统一。
- 不出现乱码、英文假字、错误书名、错别字。
- 海报上的信息必须与前面的制图提纲一致。

## 3.6 图像生成

调用图像生成工具生成最终海报。

图像指令应包含：

- 正确书名
- 用户指定 HEX 色号
- 画布比例
- 明确的中文层级内容
- “纯色背景、知识结构图、极简编辑设计、层次清楚、高可读性”等视觉约束
- 禁止擅自增加大段文字、人物、无关图标或装饰

生成后如用户说“其他都不变，只换色”，应把它视为**图像编辑任务**：保持布局、文字、层级、元素尽可能不变，只替换整体色系。

# 六、默认完整输出顺序

当用户说“帮我做《XXX》”且没有要求只做某一步时，按以下顺序：

1. `# 基本信息` 表格
2. `## 特色信息` 表格
3. 1–2 句分类说明
4. 生成五维打分图
5. `# 相关书籍` 表格
6. 生成 citation 树状图
7. `# 结构图提纲`（简洁列出最终上图文字）
8. 生成结构图海报

如果用户说“先不用制图”，只输出文字资料卡和相关书籍表，不生成三张图片。

如果用户只说“给我相关书籍表”，只执行步骤 2，不重复资料卡。

如果用户只要求“换色”，不要重新研究或改写内容，直接编辑现有图片。

# 七、语言与自媒体风格

- 中文表达自然、具体、有判断，不写学术腔套话。
- “相似点”要让普通读者一眼知道**为什么值得放在一起读**。
- 不夸大，不写“必读神作”“改变一生”一类空洞营销词，除非用户明确要更强营销风格。
- 表格内容尽量短而有信息密度，方便直接复制进 Notion、公众号、小红书素材库。
- 用户提供个人观点时，区分：`作者观点 / 书中内容 / 用户个人思考`。

- [ ] 书名、作者是否正确？

- [ ] 关联书籍是否真的存在明确思想连接？
- [ ] 关联书籍是否覆盖前置/互补/延伸/对照，而非随机同类书？
- [ ] 每本关联书的作者与年份是否核验？
- [ ] 打分图是否严格复用 `assets/score-template-reference.png` 的定版版式，并使用固定反色 Logo？

- [ ] 打分图是否正确突出道法术器类别和阅读层级？
- [ ] 雷达图、豆瓣评分是否为白色半透明体系，选中阶梯是否为 70% 透明白？
- [ ] “原创视角”是否与“道 / 法 / 术 / 器”阶梯保持安全间距？
- [ ] Citation 图是否包含目标书、4–5 本关联书、准确年份与具体关系短语？
- [ ] Citation 图是否沿用示例的树状主干、双侧节点和右侧时间轴逻辑？
- [ ] Citation 图是否与 `assets/citation-template-reference.png` 的定版排版、文字层级和连接方式一致？
- [ ] Citation 图是否已优先使用真实封面，并确保封面没有被 AI 重绘或篡改？
- [ ] 每张封面是否为正面平视图，且没有透视角度、书脊、手持背景或 3D 样机？
- [ ] 每个封面下方是否依次显示书名、作者两行，且使用定版增加后的字号，手机端清晰可读？
- [ ] 目标书下方是否只有书名和作者，没有 Keywords、标签或定位语？
- [ ] 主角书封是否明显大于关联书封，并在画面中形成清晰的第一视觉层级？
- [ ] Citation 节点是否按首次出版年份从上到下排列，且主角书位于自己的真实年份位置？
- [ ] 若任务只是换封面，是否完整保留旧版布局、连线、关系文字、时间轴与配色，并避免新增外框或卡片底板？
- [ ] Citation 分支是否以平滑曲线切入主干，没有尖锐折角或突兀斜线？
- [ ] 目标书之前的节点是否向下连接目标书，目标书之后的节点是否向上汇入主干？
- [ ] `covers/` 与 `封面来源.md` 是否齐全，封面来源和版本能否追溯？
- [ ] 结构图是否不超过 6 个一级模块？
- [ ] 海报文字是否足够精简，手机屏幕可读？
- [ ] 指定 HEX 色号是否被忠实使用？
- [ ] 用户要求“只换色”时，是否避免改动其他元素？
